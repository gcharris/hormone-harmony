## Internal Browser Testing Workflow

### How Agent 1 (Chief Architect) Uses Internal Browser

**After each section/component is built:**

1. **Open internal browser** in Cursor AI 2.0
2. **Navigate to** file or live preview
3. **Check visually:**
   - Colors match design system
   - Typography correct (fonts, sizes, weights)
   - Spacing consistent
   - Layout as specified
4. **Test interactions:**
   - Hover states on buttons/links
   - Focus states visible
   - Smooth scroll working
   - Forms respond correctly
5. **Resize viewport:**
   - Desktop (1920px, 1440px, 1024px)
   - Tablet (768px)
   - Mobile (390px, 414px)
6. **Screenshot** if needed for reference
7. **Report feedback** to builder agent

**Review checklist:**
- [ ] Matches wireframe/spec
- [ ] Uses design system components
- [ ] Content is production-ready (no lorem ipsum)
- [ ] Responsive across breakpoints
- [ ] Interactive elements work
- [ ] Visually consistent with other sections
- [ ] No console errors

## Conflict Resolution

**If agents disagree:**

**Example: Agent 5 (Riley) suggests major change, Agent 3 (Jordan) disagrees**

**Agent 5:**
```
Alex, I think the testimonial section needs more visual contrast. Current cards blend into background.
```

**Agent 3:**
```
Alex, I chose soft background intentionally - aligns with warm, approachable brand. Too much contrast could feel harsh.
```

**Agent 1 resolution:**
```
Riley, Jordan - both valid points.

Jordan, try a middle ground: keep soft background but increase border contrast slightly. Use accent color (plum) for border-left at 3px instead of current subtle treatment.

This adds visual separation without harsh contrast.

Jordan, implement this version. If it feels wrong, revert and we'll go with your original.
```

**Final decision authority:** You (Executive Director) if Agent 1 needs tie-breaker
