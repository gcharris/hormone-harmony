## 2. Accessibility Standards (WCAG 2.1 AA)

### Semantic HTML

**Document Structure:**
- [ ] Proper DOCTYPE declaration (<!DOCTYPE html>)
- [ ] HTML lang attribute set (<html lang="en">)
- [ ] Meta charset defined (<meta charset="UTF-8">)
- [ ] Meta viewport for responsive (<meta name="viewport"...>)
- [ ] One H1 per page (main headline)
- [ ] Heading hierarchy logical (H1 → H2 → H3, no skips)
- [ ] Landmarks used (<header>, <nav>, <main>, <footer>, <section>)
- [ ] Lists use proper markup (<ul>, <ol>, <li>)

**Forms:**
- [ ] All inputs have associated <label> elements
- [ ] Labels use for="" attribute matching input id
- [ ] Required fields marked with required attribute
- [ ] Error messages associated with inputs (aria-describedby)
- [ ] Fieldsets used for radio/checkbox groups
- [ ] Submit buttons use <button> not <input type="submit">
- [ ] Placeholder text NOT used as label replacement
- [ ] Form validation messages clear and helpful

**Images & Media:**
- [ ] All <img> tags have alt attribute
- [ ] Decorative images have empty alt (alt="")
- [ ] Informative images have descriptive alt text
- [ ] Icon alt text describes function, not appearance
- [ ] No "image of" or "picture of" in alt text
- [ ] Complex images (charts) have extended descriptions

**Links:**
- [ ] Link text describes destination (not "click here")
- [ ] External links indicate in text or title attribute
- [ ] External links use rel="noopener noreferrer"
- [ ] Links distinguishable from regular text (not just color)
- [ ] Visited link state visible and distinct

---

### Keyboard Navigation

**Focus Management:**
- [ ] All interactive elements keyboard accessible
- [ ] Tab order logical and follows visual flow
- [ ] Focus indicator visible on all elements (outline or ring)
- [ ] Focus indicator meets contrast requirements (3:1 minimum)
- [ ] No keyboard traps (can always tab away)
- [ ] Skip-to-main-content link at top of page
- [ ] Modal/overlay close button keyboard accessible
- [ ] Dropdown menus keyboard navigable (arrow keys)

**Interactive Patterns:**
- [ ] Buttons activated with Enter and Space
- [ ] Links activated with Enter only
- [ ] Custom controls have proper ARIA roles
- [ ] Accordion panels keyboard navigable
- [ ] Carousel controls keyboard accessible
- [ ] Form fields navigable with Tab
- [ ] Form submission possible with Enter key

---

### Color & Contrast

**Text Contrast:**
- [ ] Body text: 4.5:1 contrast minimum (WCAG AA)
- [ ] Large text (18px+): 3:1 contrast minimum
- [ ] Headings: 4.5:1 contrast (or 3:1 if large)
- [ ] Link text: 4.5:1 contrast with background
- [ ] Button text: 4.5:1 contrast with button background
- [ ] Form labels: 4.5:1 contrast
- [ ] Error messages: 4.5:1 contrast
- [ ] Placeholder text: 4.5:1 contrast (if used)

**Non-Text Contrast:**
- [ ] Icons: 3:1 contrast with background
- [ ] Focus indicators: 3:1 contrast
- [ ] Border of form inputs: 3:1 contrast
- [ ] Graphical elements: 3:1 contrast
- [ ] State indicators (hover, active): 3:1 contrast

**Color Independence:**
- [ ] Information not conveyed by color alone
- [ ] Error states use icon + text + color
- [ ] Success states use icon + text + color
- [ ] Links distinguishable without color (underline, icon, weight)
- [ ] Charts/graphs use patterns + color
- [ ] Form validation uses text + color

**Contrast Testing Tools:**
- WebAIM Contrast Checker: https://webaim.org/resources/contrastchecker/
- WAVE Browser Extension
- Axe DevTools
- Chrome Lighthouse

---

### ARIA & Assistive Technology

**ARIA Usage:**
- [ ] ARIA roles used appropriately (landmark, navigation, etc.)
- [ ] aria-label used where visible label not possible
- [ ] aria-labelledby used to associate labels
- [ ] aria-describedby used for additional context
- [ ] aria-hidden="true" on decorative elements only
- [ ] aria-expanded used on collapsible elements
- [ ] aria-current used for current page in nav
- [ ] aria-live regions for dynamic content (if applicable)

**Screen Reader Testing:**
- [ ] Test with NVDA (Windows - free)
- [ ] Test with JAWS (Windows - trial)
- [ ] Test with VoiceOver (Mac/iOS - built-in)
- [ ] All content readable by screen reader
- [ ] Navigation landmarks announced
- [ ] Form fields properly labeled and announced
- [ ] Button purposes clear
- [ ] Image alt text appropriate
- [ ] Skip links functional

**Common ARIA Patterns:**
```html
<!-- Navigation -->
<nav aria-label="Primary navigation">

<!-- Skip link -->
<a href="#main-content" class="sr-only">Skip to main content</a>

<!-- Main content -->
<main id="main-content">

<!-- Button with icon -->
<button aria-label="Close dialog">
  <span aria-hidden="true">×</span>
</button>

<!-- Expandable section -->
<button aria-expanded="false" aria-controls="section-1">
  How It Works
</button>
<div id="section-1" hidden>Content</div>

<!-- Current page -->
<a href="/about" aria-current="page">About</a>
```

## 3. Privacy & Security Requirements

### Data Protection

**General Principles:**
- [ ] Data minimization: Collect only necessary data
- [ ] Purpose limitation: Use data only for stated purposes
- [ ] Storage limitation: Don't retain data longer than needed
- [ ] User control: Users can view, export, delete their data
- [ ] Transparency: Clear privacy policy and data practices

**Technical Implementation:**
- [ ] HTTPS enabled site-wide (SSL certificate active)
- [ ] All forms submit over HTTPS
- [ ] No sensitive data in URLs (query strings)
- [ ] No sensitive data logged to console
- [ ] Session tokens secure and httpOnly (if using auth)
- [ ] Password fields use type="password"
- [ ] No autocomplete on sensitive fields (if applicable)
- [ ] CSRF protection on forms (if server-side)

**Third-Party Scripts:**
- [ ] Inventory all third-party scripts (analytics, fonts, etc.)
- [ ] Review privacy policies of third-party services
- [ ] Ensure third parties are GDPR/CCPA compliant
- [ ] Load scripts asynchronously where possible
- [ ] Use Subresource Integrity (SRI) for CDN scripts
- [ ] Cookie consent banner if using tracking cookies
- [ ] Users can opt out of analytics

---

### Privacy Policy Requirements

**Must Include:**
- [ ] What data is collected (name, email, etc.)
- [ ] How data is collected (forms, cookies, analytics)
- [ ] Why data is collected (newsletter, support, analytics)
- [ ] How data is used (stated purposes only)
- [ ] How data is protected (encryption, access controls)
- [ ] Who data is shared with (never sold - state this clearly)
- [ ] How long data is retained
- [ ] User rights (access, correction, deletion, portability)
- [ ] How to exercise rights (contact email)
- [ ] How to opt out of marketing
- [ ] Cookie policy (if using cookies)
- [ ] Changes to policy (how users notified)
- [ ] Contact for privacy questions
- [ ] Effective date of policy

**GDPR Compliance (if serving EU users):**
- [ ] Legal basis for processing stated
- [ ] Right to be forgotten (data deletion)
- [ ] Right to data portability
- [ ] Consent must be explicit and opt-in
- [ ] Withdrawal of consent easy
- [ ] Data breach notification procedures
- [ ] Data Protection Officer contact (if applicable)

**CCPA Compliance (if serving California users):**
- [ ] Right to know what data collected
- [ ] Right to delete data
- [ ] Right to opt out of data sale
- [ ] "Do Not Sell My Personal Information" link (if applicable)
- [ ] No discrimination for exercising rights

---

### Security Best Practices

**Headers & Configuration:**
- [ ] Content-Security-Policy header set
- [ ] X-Content-Type-Options: nosniff
- [ ] X-Frame-Options: DENY or SAMEORIGIN
- [ ] Referrer-Policy: strict-origin-when-cross-origin
- [ ] Permissions-Policy restricts unnecessary features

**Form Security:**
- [ ] Server-side validation in addition to client-side
- [ ] Input sanitization to prevent XSS
- [ ] SQL injection prevention (parameterized queries)
- [ ] Rate limiting on form submissions
- [ ] CAPTCHA or honeypot for SPAM prevention
- [ ] No sensitive data sent via GET requests
- [ ] Form data encrypted in transit (HTTPS)

**Dependencies & Updates:**
- [ ] All dependencies up to date (no known vulnerabilities)
- [ ] Regular security audits scheduled
- [ ] npm audit or similar run regularly
- [ ] Dependency scanning enabled (e.g., Dependabot)

## 4. Performance Optimization

### Page Load Speed

**Target Metrics:**
- [ ] First Contentful Paint (FCP): < 1.8s
- [ ] Largest Contentful Paint (LCP): < 2.5s
- [ ] Time to Interactive (TTI): < 3.5s
- [ ] Total Blocking Time (TBT): < 200ms
- [ ] Cumulative Layout Shift (CLS): < 0.1
- [ ] Speed Index: < 3.4s

**Optimization Techniques:**
- [ ] Images optimized (compressed, modern formats)
- [ ] CSS minified
- [ ] JavaScript minified
- [ ] Critical CSS inlined
- [ ] Deferred JavaScript (async or defer attributes)
- [ ] Lazy loading for images below fold
- [ ] Font preloading for critical fonts
- [ ] Gzip or Brotli compression enabled
- [ ] Browser caching configured (Cache-Control headers)
- [ ] CDN used for static assets (if applicable)

---

### Image Optimization

**Best Practices:**
- [ ] All images compressed (TinyPNG, ImageOptim, etc.)
- [ ] Images sized appropriately (no 4K images for 400px display)
- [ ] WebP format used with JPEG/PNG fallback
- [ ] Responsive images with srcset for different sizes
- [ ] Images lazy loaded (loading="lazy" attribute)
- [ ] Icon sprites or inline SVG for icons
- [ ] Hero images preloaded (if critical)
- [ ] Alt text on all images (accessibility + SEO)

**File Size Targets:**
- [ ] Hero images: < 150KB
- [ ] Section images: < 100KB
- [ ] Icons: < 10KB (SVG preferred)
- [ ] Thumbnails: < 50KB

---

### Code Optimization

**HTML:**
- [ ] Semantic, minimal markup
- [ ] No inline styles (use external CSS)
- [ ] No unused markup or comments in production
- [ ] Proper use of heading hierarchy

**CSS:**
- [ ] Remove unused CSS (PurgeCSS or similar)
- [ ] Combine multiple stylesheets
- [ ] Minify CSS for production
- [ ] Use CSS variables for consistency
- [ ] Avoid !important overrides
- [ ] Mobile-first media queries

**JavaScript:**
- [ ] Remove unused JavaScript
- [ ] Combine multiple scripts
- [ ] Minify JavaScript for production
- [ ] Use async or defer attributes
- [ ] Avoid document.write()
- [ ] No console.log() in production
- [ ] Event delegation for repeated elements

---

### Performance Testing

**Tools:**
- [ ] Google PageSpeed Insights (desktop + mobile)
- [ ] Chrome Lighthouse (in DevTools)
- [ ] WebPageTest (webpagetest.org)
- [ ] GTmetrix
- [ ] Pingdom Website Speed Test

**Testing Checklist:**
- [ ] Test homepage performance
- [ ] Test internal pages performance
- [ ] Test on 3G connection (slow network)
- [ ] Test on different devices (desktop, mobile, tablet)
- [ ] Score 90+ on Lighthouse Performance
- [ ] Score 90+ on PageSpeed Insights (mobile)
- [ ] Load time under 3 seconds on 4G
- [ ] No render-blocking resources
